# КТ2: Примерка роли Product Manager (Mos.ru)

## Исходное задание
- **Компания:** Mos.ru
- **Роль:** Junior Product Manager
- **Источник:** [Сборник тестовых заданий на Хабре](https://habr.com/ru/articles/656579/) (Задание №5, 2022)
- **Дата выполнения:** 2026 год

## Что было сделано
1. Проанализированы 4 лучших личных кабинета на рынке как бенчмарки ([docs/benchmarks.md](docs/benchmarks.md))
2. Сформулированы 5 конкретных улучшений для ЛК MOS.ru с привязкой к бизнес-метрикам ([docs/improvements.md](docs/improvements.md))
3. Описан пошаговый процесс внедрения этих улучшений от идеи до запуска ([docs/process.md](docs/process.md))

## Что НЕ было сделано и почему
- **Детальные User Stories для каждого улучшения:** не хватило времени, на этапе идеи важнее согласовать общую концепцию и метрики с заказчиком
- **Прототипы в Figma:** сначала необходимо валидировать гипотезы и получить согласие стейкхолдеров, чтобы не тратить время дизайнера впустую
- **Расчёт Unit-экономики:** отсутствуют внутренние данные по текущей стоимости привлечения и удержания пользователя в MOS.ru

## Взгляд смежной роли (Backend-разработчик)
Перед финализацией документация была проверена с точки зрения Backend-разработчика (моя смежная роль из КТ1). Были выявлены и учтены следующие риски:
1. **Умные уведомления:** потребуют новой таблицы в БД для хранения триггеров и расписания. Добавлено требование к API в документацию.
2. **Чат-бот с ИИ:** требует оценки нагрузки на серверы или бюджета на внешнее API. Добавлен пункт "Технические требования" в бэклог.
3. **История документов:** необходимо учесть требования 152-ФЗ о сроках хранения персональных данных. Добавлено требование к compliance.
